# fixmystreets.gr - security review of the custom code (read-only)

Scope: Greece cobrand Perl (Cobrand/Greece.pm, Map, PhotoStorage, App/Controller/Greece*.pm), bin/greece/*, templates/web+email/greece, web/cobrands/greece/*.js, docker/greece/{video,anonymiser,overlay}, conf/nginx.conf-docker, docker-compose.yml, data/greece/*.sql.
Method: code reading on the fms VM (/opt/fixmystreet, git HEAD of the working tree) plus config key names only (no values). One harmless GET pair against the live site to confirm finding H1 (own session only). No exploitation, no brute force, nothing changed.
Date of review: 2026-10-29. Line numbers are absolute lines of the files as they are in the working tree.

Severity counts: High 2, Medium 9, Low 14, Info 12.

Things checked and found OK (so nobody repeats the work):
- TT output is auto-escaped (FixMyStreet::Template::Stash/Context, View/Web.pm CLASS => FixMyStreet::Template); only the `| safe` / mark_safe uses were reviewed: all are static strings or admin-set data (category_extras_fields.html meta.description comes from contact extra data; alert/index.html location_error is upstream). No XSS found in the Greece templates. The unescaped-looking outputs (problem_row.html dl.rcpts, information.html problem.name) are auto-escaped.
- JS innerHTML uses (nearby-check.js, place-search.js, dimos-search.js, email-otp.js, video-upload.js, votes.js, report-stepper.js) build from constants, numbers or escaped strings (esc()/escape()/encodeURIComponent). No eval, no document.write, no postMessage.
- SQL: every raw dbh call in Greece code uses placeholders or constants (GreeceRequests.pm, GreeceVote.pm, greece_ref/greece_ref_to_id, bin/greece/*). The only interpolated values are constants ($TODAY, $HOURS, $REPORT_MONTHS) or ints. mail-delivery builds SQL from log data but only ints and quote-doubled JSON reach it.
- GreeceSocial.pm (Google/Apple/Microsoft): signed state with expiry, cookie binding compared in constant time, nonce, aud, iss/tid checks, RS256 only, JWKS refresh, _safe_return rejects // and /\, staff and superuser accounts refused, unverified emails not passed on. Good.
- CSRF: state-changing admin/account endpoints (Approve, Requests, Account, Edit, Password reset) call /auth/check_csrf_token (HMAC bound to the session id). JSON endpoints (OTP, Video, Vote) require X-Requested-With and the site sends no CORS headers (only app://localhost in Root.pm:199), so cross-site forms cannot reach them.
- No secrets, keys or tokens are committed (git ls-files has no .env/.pem/.p8/general.yml-local; grep for key material in docker/, bin/, conf/ is clean). publish-public.sh has a private-detail guard. Anonymiser Dockerfile verifies the YuNet model by sha256.
- Public JSON checked with harmless GETs: /around?ajax=1 (pins: id, category title, coordinates only), /report/ajax/<id> and /open311/v2/requests.json for a public police complaint (EV/obstacle category) show no reporter name, email, phone or plate (the plate is masked in detail, greece_detail_full and pinakida are not output), and the recipient is the body name only. /report/<id>/json is not a route (404). Photo URLs of hidden/private reports are access-checked at the origin (upstream Photo.pm) - see L14 for the caching headers. I did not look for hidden/private report ids on the live site.
- `| safe` in email/greece/_text_email.html:22 is applied to the text part rendered by INCLUDE inside the autoescaping TT instance used for the .html part (FixMyStreet/Email.pm:186-189; only the .txt part is rendered with autoescape off), so user content in it is already HTML-escaped; a URL typed by a user in a report is made clickable (low-grade phishing aid in our own emails). No other `| safe` or mark_safe in templates/email/greece takes user data.
- Turnstile coverage: report/new, report/new/mobile, report/update, contact, alert/subscribe, auth email sign-in, /greece/privacy and /greece/password/forgot check it; /greece/otp/send, /greece/video/*, /greece/photo/upload, /photo/upload and /import do not (see M4, M7, H2).
- Access control: Approve, Handbook, Requests, Video view are superuser/staff gated in the controller; Photo.pm (upstream) refuses photos of hidden/non_public reports to anyone but owner/staff; Edit requires the author and a non-anonymous visible report; vote only for visible public reports.

## HIGH

### H1 - STAGING_SITE=1 on the live site lets any visitor switch the cobrand and so skip every Greece-specific control (2FA gate, Turnstile, ...)
- Where: perllib/FixMyStreet/App.pm:195 (setup_dev_overrides, 274-300), 168-173 (_get_cobrand uses get_override), conf/general.yml-local (STAGING_SITE: 1, ALLOWED_COBRANDS: greece only); consumers: perllib/FixMyStreet/Cobrand/Greece.pm:210 (check_login_disallowed -> greece_2fa_gate 866), 133 (greece_turnstile_ok), 104/111 (never_confirm / anonymous reports), all GreeceXxx controllers that 404 when moniker ne greece.
- What: with STAGING_SITE true, any request carrying a query parameter `_override_cobrand_moniker=<anything>` stores it in the visitor's session (4-week cookie) and from then on the request runs under that cobrand. get_class_for_moniker falls back to FixMyStreet::Cobrand::Default for any name that is not in ALLOWED_COBRANDS, so `?_override_cobrand_moniker=x` gives the stock Default cobrand. Verified live (own session): GET /about/terms returns the Greek page (200, class gr-*), the same URL with `?_override_cobrand_moniker=default` returns a 404 page of the stock cobrand with no Greek markup. All behaviour that lives in the Greece cobrand hooks then no longer applies to that session.
- Abuse: (1) the emailed second factor for superusers/body staff is implemented only as the Greece check_login_disallowed hook (Greece.pm:210 -> 866-884) - an attacker who has a staff password (or the emailed sign-in link) adds the override once and is never sent to /greece/2fa; must_have_2fa 'skip' also disappears, so no 2FA at all. (2) Turnstile on report/update/contact/alert forms is checked only in Greece hooks (133, 226, 322, 702; alerts 210-225): bypassed. (3) Other Greece rules (name filter, bad-word hold, nsfw hold, plate masking in greece_public_complaint, approval gate for municipalities) are cobrand hooks too; reports created under Default are stored without them (the DB is shared). The nginx rate limits still apply. _override_lang is settable as well.
- Severity: high while STAGING_SITE is 1 (it disappears when the site goes live with STAGING_SITE 0, but then also `send_reports` staging behaviour changes - plan the flip together).
- Fix: set STAGING_SITE: 0 on the public host and use STAGING_FLAGS-style behaviour only on a non-public staging copy; or, if staging mode must stay, block the parameter at nginx (`if ($args ~* "(^|&)_override_") { return 400; }` in @catalyst and the static locations) or override setup_dev_overrides in Greece.pm to do nothing. Also make the 2FA gate independent of the cobrand (e.g. in Root.pm auto, or by a check in Auth sign-in) so a cobrand switch cannot skip it.

### H2 - Anonymous, unauthenticated video upload can fill the disk and burn CPU (shared host volume)
- Where: perllib/FixMyStreet/App/Controller/GreeceVideo.pm:83-105 (start), 107-126 (chunk), 128-138 (finish), sweep 68-81; conf/nginx.conf-docker:15, 131-149; docker-compose.yml:23,89,189.
- What: start/chunk/finish need only the X-Requested-With header: no Turnstile, no signed-in user, no confirmed email (the confirmed-email check is applied only when the report is saved, Greece.pm:314-321 in report_check_for_errors, after the bytes are on disk). nginx limits only `start` (6/min per CF-Connecting-IP, burst 3); `chunk` (up to 10 MB each, unlimited rate) and `finish` have no limit. Each start allows size up to 300 MB (MAX_UPLOAD line 38) and the declared size is not tied to anything else, so one IP can write about 1.8 GB/min; a few IPs (the header is whatever Cloudflare saw) fill the fixmystreet-videos volume, which lives on the same host disk as postgres and the photo uploads. The sweeper (_sweep) runs only inside `start` and removes incoming/ after a day, so the damage is done long before. `finish` queues an ffmpeg transcode on every call and the queue in video/app.py:32,153-157 is unbounded (calling finish repeatedly re-enqueues; the second run overwrites status.json with "not_video" because the source was deleted, harmless but wasteful).
- Fix: require a passed Turnstile (or signed-in user) in `start`; per-session and global byte quota (sum of incoming/ size) and a hard cap on concurrent incoming/ dirs; nginx limit_req on chunk/finish and limit_conn; run the sweep from cron only (bin/greece/video-sweep already exists) and a quota on the volume (separate filesystem or project quota); make `finish` idempotent (reject when status.json exists); bound the video queue.

## MEDIUM

### M1 - Anyone can hide any report from the public map with one POST (mass takedown)
- Where: perllib/FixMyStreet/App/Controller/GreecePrivacy.pm:24-62; conf/nginx.conf-docker:33 (limit 2/min per IP, burst 5).
- What: /greece/privacy/<id> needs only a Turnstile pass (skipped for any signed-in user, Greece.pm:136) and sets non_public=1 on a report that is not hidden/unconfirmed. Ids and the date-number refs are sequential and public, so a script (Turnstile token from a solving service, or a throwaway signed-in account, which needs only an email link) can hide every report on the site; nothing is restored automatically, only an admin can undo each one. The reason/contact are free text stored in extra and mailed to the contact address (no per-report or global cap on those mails). The design note says "a wrong flag costs a few hours" - not true under automation.
- Fix: hide only after N distinct flags or an admin glance for reports older than e.g. 24 h; per-report and global rate limit (a report can be flagged once; max M flags/hour site-wide, with an alarm); or hide only the photo/text, not the whole report; log flagger IP/session so abuse is traceable.

### M2 - /greece/nearby-private is an unauthenticated location oracle for private police complaints
- Where: perllib/FixMyStreet/App/Controller/GreeceNearby.pm:26-58 (no rate limit in nginx).
- What: for any lat/lon it answers how many non-public open reports exist within 100 m in the last 24 h and how many minutes ago the latest was. Repeated on a grid (cells 20-30 m apart) it gives the position of a complaint to ~10-20 m and its time to the minute. The complaint is private exactly because it can name a vehicle/person; someone who was reported (neighbour dispute, shop, parked car) learns roughly where and when the reporter stood. No auth, no Turnstile, no limit.
- Fix: require the report-form context (Turnstile/session), rate limit per IP and per session, coarsen the answer (count capped to "1+", minutes to 30-minute buckets), and/or only answer for the pin the same session just placed.

### M3 - Emailed second factor and the OTP: attempt counters are racy, no network rate limit, and the "2FA" shares the channel with the sign-in link
- Where: GreeceTwoFactor.pm:53-73 (read tries, increment, update: not atomic; token re-selected each request by _current 87-92), GreeceOTP.pm:81-87 (same pattern); conf/nginx.conf-docker: no limit on /greece/2fa or /greece/otp/check; templates/web/greece/auth/greece_2fa.html:12-23 (forms have no CSRF token); GreeceTwoFactor.pm:75-83 (a GET sends a code).
- What: each code is 6 digits from /dev/urandom (fine: 1e6 space, 10-15 min, 5 tries, only a hash stored). The 5-try limit is a read-modify-write on the token row, so N parallel POSTs that arrive before the first update each get a try: tries are not bounded by 5. With 5 codes per 15 min per account (_send 96-99) and ~10 parallel workers, an attacker who has a staff password can test ~50 codes per 15 min (about 0.5 percent a day) - weak but real, and nginx adds nothing. The OTP (email confirmation) has the same race but protects little. A cross-site request to /greece/2fa can make a signed-in staff browser trigger code emails (capped 5/15 min) because there is no CSRF token. For accounts that sign in with the emailed link, the second factor is the same mailbox, so it adds nothing against mailbox compromise (info).
- Fix: do the increment in SQL (UPDATE token ... SET tries = tries+1 ... WHERE tries < 5 RETURNING) or SELECT ... FOR UPDATE; delete the token on the 5th wrong try inside the same transaction; add limit_req on /greece/2fa and /greece/otp/check; add the csrf token to the 2FA forms and send codes only on POST; consider TOTP/WebAuthn for superusers.

### M4 - Photo upload is unthrottled and the anonymiser has no size/pixel limit (availability)
- Where: PhotoStorage/Greece.pm:57-66 (every JPEG goes to the service), docker/greece/anonymiser/app.py:176-177 (cv2.imdecode of a body up to 15 MB, no pixel cap), 332-389 (ThreadingHTTPServer, one thread per request, models in one process), docker-compose.yml:163-178 (mem_limit 1536m, no cpus limit; the image has no USER, so it runs as root); nginx: no limit_req for /photo/upload or /greece/photo/upload, no Turnstile.
- What: an anonymous client can POST up to 10 MB JPEGs without limit. A JPEG that declares a huge size (e.g. 30000x30000) compresses to a few KB-MB and decodes (OpenCV default cap 2^30 pixels) to GBs: the container has 1.5 GB, so it is OOM-killed and restarted; while it is down every upload fails closed (by design), so reports with photos cannot be filed. Normal photos cost seconds of ALPR+face+NudeNet CPU each on a shared VM. The web container's ImageMagick (upstream PhotoSet.pm ~190) has the same pixel-bomb exposure.
- Fix: check dimensions with a header-only reader before decode (reject > ~40 MP), set OPENCV_IO_MAX_IMAGE_PIXELS and ImageMagick policy.xml limits, bounded worker pool and request timeout, cpus limit, non-root USER, nginx limit_req/limit_conn on photo upload, Turnstile or a signed-in session for the first upload.

### M5 - The 45-second video limit can be bypassed with crafted container metadata
- Where: docker/greece/video/app.py:85-93 (duration is taken from format.duration / stream duration), 95-101 (the ffmpeg command has no -t and no -fs), 101 (timeout 600 s); GreeceVideo.pm:38 (300 MB).
- What: the duration fields are written by the uploader (mvhd/tkhd, Matroska Segment info). A file whose headers say 10 s but holds many minutes of video passes, is transcoded for up to 10 minutes of 2 CPU cores and stored as ready/<id>.mp4 (a day if unclaimed, 180 days if claimed) with no size cap. Only the zero-duration case is verified by decoding (decoded_seconds). ffmpeg also decodes untrusted 4K+ streams with no frame-size limit.
- Fix: always pass -t 46 (and -fs) to the transcode, or probe the real last packet timestamp; reject frame sizes above 4096x4096; keep the format whitelist (good) and -protocol_whitelist file (good); apply ulimits.

### M6 - Retention/anonymisation promise is not met for several personal fields
- Where: bin/greece/anonymise-old lines 45 (@PERSONAL_EXTRA), 51-53 (query), 60-85 (what is cleared); bin/greece/retention; bin/greece/dsar.
- What: after 24 months a report is "anonymised": title/detail/photo/name/user replaced, phone and a few extra keys unset. Not touched: (a) the plate number a reporter typed into the police-complaint question (extra->'_fields', field pinakida, read by Problem::greece_plate): a third party's plate stays with the point and date; (b) moderation_original_data rows (upstream keeps the original title/detail/photo of a moderated report); (c) problem.geocode/postcode text; (d) greece_vote rows of an anonymised account and its alert rows are not mentioned; (e) greece_request rows keep the citizen email 3 years by design but dsar erase neither lists nor deletes them, and dsar export omits greece_vote and greece_request. The inactive-account job also anonymises accounts that only receive alerts (last_active moves on sign-in only) after a warning mail. I did not query the database to confirm the contents of these columns (read-only review).
- Fix: clear _fields (at least pinakida), moderation_original_data and geocode; extend dsar to greece_vote/greece_request/alerts; decide whether alert-only users count as active.

### M7 - Mail-abuse paths: unauthenticated OTP and account emails to arbitrary addresses, thin limits
- Where: GreeceOTP.pm:49-73 (no Turnstile; limits 6/session, 3/address/hour, 200/hour global; nginx 3/min per IP, conf:17,122-130); Greece.pm:586-605 (report_new_munge_after_insert mails an account link, with the typed name, to whatever email was typed on a report); GreecePassword.pm:31-65 (not in the nginx form_posts regex, conf:33, which lists /auth/forgot but not /greece/password/forgot; per-account 3/h, Turnstile only).
- What: (1) anyone can make the site mail an OTP, or an account-link, to any third-party address (harassment from our domain, relay reputation: the comment in GreeceOTP.pm:60 itself worries about Outlook); (2) the 200/h global cap is a cheap DoS of the OTP feature from two IPs (a report with a video needs the OTP); (3) a report typed with a victim's email is filed under the victim's account (never_confirm_reports) and the letter to the municipality carries the victim account's stored phone number (Greece.pm:78-79); (3b) the upstream /import endpoint (nginx.conf-docker:33 lists it, Report/New.pm report_import) is not behind Turnstile at all (it does not call report_check_for_errors): one POST creates a user row for any email, stores a partial report and mails partial.txt to that address; (4) password sign-in (/greece/auth) is limited per IP only: no lockout, HIBP check off (CHECK_HAVEIBEENPWNED 0), so a botnet can try common passwords at 2/min per IP.
- Fix: disable /import and /report/new/mobile (the site has no mobile app) in nginx or with a cobrand hook; Turnstile (or session proof) on /greece/otp/send; per-IP and per-recipient-domain daily caps; do not attach a report to an existing account unless the email is confirmed (use the shared anonymous account and keep the typed email on the report only); add /greece/password/forgot to the nginx form_posts regex; progressive delay/lockout on failed password sign-ins; enable HIBP or a local common-password list.

### M8 - Open redirect after the 2FA step: /greece/2fa?r=/%5Cevil.example works for ANY signed-in user
- Where: GreeceTwoFactor.pm:43-46 (the check `m{^/(?!/)}` accepts a backslash as the second character; line 46 redirects immediately, with no code needed, whenever the account does not need 2FA (every citizen, and staff who already entered the code), and line 65 after a correct code), Greece.pm:878-882 (the gate builds r from /auth?r= with a pattern that also lets a leading backslash through). GreeceSocial._safe_return does reject `\`; this one does not.
- What: I read Catalyst's Response::redirect inside the container: the location string is stored and sent verbatim (no URI normalisation; Engine.pm does not touch it), so the header is `Location: /\evil.example`, which Chrome, Edge and Firefox resolve to https://evil.example. A link on our trusted domain that, for anyone signed in (or after a staff member types the real code), lands on an attacker page: phishing for credentials or staff 2FA codes. Not tested live (needs a session).
- Fix: validate with `^/(?![/\\])` (and reject control characters), or build the target with $c->uri_for($path) like Auth::redirect_on_signin; apply the same rule in greece_2fa_gate.

### M9 - bin/greece/retention deletes every token after 7 days, including alert unsubscribe links
- Where: bin/greece/retention:29-30 (`DELETE FROM token WHERE created < now() - interval 7 days`, all scopes); upstream perllib/FixMyStreet/Script/Alerts.pm:436-448,480 (every alert email carries `/A/<token>`, scope alert, type unsubscribe, stored in the token table), Alerts.pm:209-214 and Problem.pm:644-668 (scope alert_to_reporter /R/ links and email_sign_in /M/ links), App/Controller/Tokens.pm:233-269 (load_auth_token: no token found gives the "token too old" 400 page).
- What: the rule's comment assumes only sign-in links/codes and unconfirmed alert confirmations live in token. But unsubscribe links in alert emails and the update/login links in mails to reporters use the same table and are meant to work as long as the mail exists. After 7 days the "stop these emails" link in every alert email returns an error. Anonymous alert subscribers have no account to unsubscribe from, so the only way left is writing to the contact address: an ePrivacy/GDPR (easy withdrawal) problem created by our own script. I did not look at the production token table.
- Fix: restrict the rule to the short-lived scopes (email_sign_in, greece_otp, greece_2fa, greece_reset, partial, alert with type subscribe/confirm and data->>'type' = 'subscribe'), or have the unsubscribe link carry a self-contained HMAC (user/alert id + signature) instead of a stored token.

## LOW

### L1 - mail-delivery trusts forged bounce mails (VERP hash not checked)
- Where: bin/greece/mail-delivery:143-146 (`fms-report-(\d+)-[0-9a-f]+@`, `fms-digest-([0-9a-z]+)@`: the hash/token is not verified), 156-171 (envelope From/To/Final-Recipient/Status taken from a mail anyone can send, because every address of the domain lands in bounces@), 116 (psql as the postgres superuser).
- What: anyone can mail fms-report-<id>-aaaa@fixmystreets.gr with a fake DSN and flip that report's greece_delivery to bounced/deferred (hides the public "delivered" check, shows a warning to staff, triggers the notification mail to falcon@ and fills it with attacker-chosen subject/diagnostic text). Values are escaped on the way into SQL and into the admin template (auto-escape), so this is integrity/nuisance only.
- Fix: verify the VERP hash the same way FixMyStreet's bounce handler does, only accept DSNs (multipart/report) from the relay/MX, and use a least-privilege DB role for the script.

### L2 - Upload fallbacks that skip the anonymiser (and keep EXIF)
- Where: PhotoStorage/Greece.pm:55 (only data starting with the JPEG magic is anonymised; anything else is stored unchanged); upstream App/Model/PhotoSet.pm ~191-196 (`$photo_blob = try { ImageMagick ... as_blob(JPEG) } catch { $photo_blob }`).
- What: normally ImageMagick re-encodes every upload to a stripped JPEG, so the anonymiser sees it. If the conversion throws (resource limit, a PNG/GIF/TIFF/WebP that Image::Size accepts but ImageMagick refuses), the raw upload is stored as is: no plate/face blur, no NSFW check, EXIF GPS/device kept. Only reachable with crafted files, and the result must still be displayable, but it defeats the "no photo is stored unblurred" promise in the module's header.
- Fix: in store_photo, refuse (die) when the blob is not a JPEG instead of storing it, except for the admin logo paths; or re-run the conversion strictly and fail the upload on error.

### L3 - Turnstile is fail-open and remembered for 12 hours per session
- Where: Greece.pm:147-150 (Cloudflare 5xx/timeout lets the form through), 158 (session remembers a pass for 12 h; a single solved check authorises unlimited forms from that session cookie), 145-146 (no check of the returned hostname/action).
- What: a bot that solves one challenge (or buys tokens) can script the session for 12 hours, bounded only by nginx's 2/min per IP; sessions are free to create. Fail-open is a deliberate choice but means an outage (or a filtered route to challenges.cloudflare.com from the server) silently disables the protection.
- Fix: remember the pass for minutes (or per form), verify `hostname` and `action` in the siteverify answer, alert on the fail-open branch.

### L4 - Account enumeration on /greece/auth, and timing on password reset
- Where: GreeceAuth.pm:28-38 (a wrong password for an existing account with a password gives the "password incorrect" page; an unknown email, or an account without a password, silently gets the "we sent you a link" page); GreecePassword.pm:53-64 (an email is only sent when the account exists and is verified, so the response time differs).
- Fix: when a password is given for an unknown address, run a dummy hash check and answer with the same generic message; send the reset mail asynchronously or pad the time.

### L5 - Password reset does not revoke existing sessions
- Where: GreecePassword.pm:96-100 (sets the password and deletes the reset tokens only).
- What: a stolen session cookie (4-week lifetime, App.pm:69-72) survives the owner's password reset. Superuser/staff sessions also keep greece_2fa=<id> for their whole lifetime.
- Fix: delete the user's rows in the session table (or bump a per-user epoch) on password change and on 2FA failures; shorten staff sessions.

### L6 - Approve-then-edit: the digest sends whatever text is current, not what was approved
- Where: GreeceApprove.pm:45-50 (approval stores {at, by} per report id), GreeceEdit.pm:34-91 (the author may edit the description until it is sent), bin/greece/send-digest:203 (detail taken at send time); "approve all" (GreeceApprove.pm:45) also approves reports that arrived after the page was rendered.
- Fix: store a hash of title+detail with the approval and treat an edit after approval as needing approval again; make "approve all" apply only to the ids shown.

### L7 - Existence/date of hidden and private reports leaks through the number redirect
- Where: Greece.pm:853-860 (greece_report_number_redirect: /report/<id> answers 301 to /report/<YYYYMMDD-NN> for any existing id, including hidden and non_public reports), 1355-1369 (greece_ref_to_id does not filter state), GreeceReportRef.pm:25-30 (legacy-number redirect for any problem of the cobrand).
- What: an unauthenticated client can enumerate which ids exist and their creation date, including reports hidden for privacy or held for moderation (a 404 is returned only for ids that do not exist). The report page itself is still access-checked (/report/display).
- Fix: only redirect when the report is visible to the requester (use the same visibility test as report/display, otherwise fall through to the normal 404/403).

### L8 - Vote stuffing
- Where: Greece.pm:1074-1089 (greece_voter: an anonymous voter is a random cookie), GreeceVote.pm:20-49, nginx limit 20/min per IP.
- What: clearing the gr_voter cookie gives a new voter, so counts can be pushed by anyone (about 30 votes/min/IP); signed-in voters are one per account.
- Fix: treat votes from cookie voters as soft (separate count), add per-IP-per-report limits, or require a session with a passed Turnstile.

### L9 - Container hardening: web container has rw cgroup access and a mutable code mount
- Where: docker-compose.yml:40 (`cgroup: host`), 109 (`/sys/fs/cgroup:rw`), 72-76 and 91 (GreeceReportRef/Approve/Handbook/Requests controllers and templates/web/greece mounted without :ro), 30 (image fixmystreets-gr:latest based on fixmystreet/fixmystreet:stable, mutable tag), 163-178 (anonymiser runs as root).
- What: the app container runs systemd with a writable host cgroup mount; a code-execution bug in the app (or in ImageMagick/jhead) has a shorter path to the host, and a compromised app can persist by editing the bind-mounted code in the git working tree.
- Fix: drop the rw cgroup/host cgroup mode if systemd-in-container is not strictly needed (or use a read-only cgroup with a user namespace), mount all code :ro, pin base images by digest, run the anonymiser as non-root with no-new-privileges and a read-only root filesystem.

### L10 - OTP/2FA codes are stored as unsalted sha256(code + email|user id)
- Where: GreeceOTP.pm:68,87; GreeceTwoFactor.pm:62,104.
- What: with a database leak the 1e6 codes are brute-forced instantly; the window is limited by the 10/15-minute expiry and by bin/greece/retention deleting tokens after 7 days (not on use for failed ones), so impact is small.
- Fix: HMAC with the server secret (DB::Secret) and delete expired tokens in the same request.

### L11 - Video staging directory permissions and TOCTOU
- Where: GreeceVideo.pm:89,95-96 (chmod 0777 on the shared volume directories and each upload dir, 0666 on the upload file), 112-122 (size check then append, not atomic: two simultaneous chunks at the same offset both append).
- What: any process in either container (or a compromised video service) can rewrite or delete another visitor's upload and the ready/ files; a client can corrupt only its own upload (finish then refuses on size). The ffmpeg process runs as non-root fmsvideo (good).
- Fix: shared group + 0770/0660, flock around the append, create the directories once at deploy time.

### L12 - The shared anonymous account and every @fixmystreets.gr address land in one catch-all mailbox
- Where: bin/greece/mail-delivery:25-28 (bounces@ receives every address of the domain without its own mailbox), GreeceAuth.pm:36-38 (the email sign-in link works for any address, including the shared anonymous account; GreecePassword.pm:55 excludes it only for the reset path), Greece.pm:119-122.

### L13 - Photo responses carry `Cache-Control: public` (also for private reports served to their owner/staff)
- Where: upstream App/Controller/Photo.pm:49-90 (index/output) serves photos of non_public reports to the owner and staff with the same headers; live check: GET /photo/<id>.0.fp.jpeg on a public report returns `Cache-Control: public`, `Last-Modified`, and `cf-cache-status: DYNAMIC` (Cloudflare does not cache it today: two requests, both DYNAMIC).
- What: no leak today, because Cloudflare treats the URL as dynamic, but the headers explicitly allow shared caches and a future cache rule for *.jpeg (a common Cloudflare setting) would cache a private photo fetched by its owner or staff and serve it to anyone, and a privacy flag would not purge it.
- Fix: send `Cache-Control: private, no-store` when the report is non_public (and when the user is staff), keep public only for visible public reports, and purge the CDN URL when a report is hidden.

### L14 - Retention gaps: reports left in state partial are never purged; anonymise-old skips rows whose extra is NULL
